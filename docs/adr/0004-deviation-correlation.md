# ADR-0004: 逸脱の終了を開始イベントとタスク実行に対応付ける

## ステータス

提案中（レビュー指摘 R03 に基づく実装。承認は PR レビューで行う）

## 日付

2026-09-23

## コンテキスト（背景）

同じ種類の逸脱を最後に開いた順に閉じると、並行タスク間で終了先を取り違える。要求 Spec REQ-010・015 の逸脱表示とタスク状態が矛盾する。

## 判断（Decision）

- `deviation.closed` の `payload.opened_by` は案件内の開始イベント ID を参照する。種類・task・iteration の一致と未終了を確認する。
- 開始時のタスク投入 seq を実行の識別子として状態に保持し、同じ ID の再投入を区別する。終了時は開始に対応した実行だけを更新する。
- 参照のない旧データは、同じ種類・task・iteration・現在のタスク実行で未終了の候補が一意の場合だけ閉じる。タスクのない案件単位の逸脱も一意性を要求する。
- 不一致・存在しない参照・二重終了・曖昧な旧形式は状態を変更せず、説明欄に対応先を確認できない旨を表示する。参照不一致から別候補へフォールバックしない。
- 他の未解消例外が同じ実行に残る間、終了イベントだけでタスクを実行中にしない。

## 理由（Rationale）

イベント ID と投入 seq は既存形式にある。追加の ID 発番系を作らず、既存データの再生と並行実行の識別を両立できる。

## 検討した代替案

| 代替案 | メリット | デメリット | 却下理由 |
|---|---|---|---|
| 同種の最後を閉じる | 単純 | 別タスクを閉じる | 対応付けが不正確 |
| task だけで閉じる | 追加項目が少ない | 同タスクの重複例外・再実行を区別できない | 開始と実行の識別が必要 |
| 全既存データへ参照を必須化 | 常に明示的 | 原記録の補足・再生成が必要 | 旧データの一意な場合は安全に再生可能 |

## 影響（Consequences）

### ポジティブな影響

別タスク・別周・同じ周の再投入・二重終了に回帰テストを置ける。

### ネガティブな影響（トレードオフ）

曖昧な旧記録は未解消のまま残る。タスク開始前など実行を特定できない記録からタスク状態を推測しない。

### 将来の注意事項

新しい再構成データでは開始参照を明示する。実行基盤を実装する際の run ID・復旧方式は本リプレイのスコープ外。
