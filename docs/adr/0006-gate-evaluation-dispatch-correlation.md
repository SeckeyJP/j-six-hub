# ADR-0006: ゲート判定をタスクの投入試行へ対応付ける

## ステータス

提案中（2026-09-26 のリプレイ境界修正。PR で確認する）

## 日付

2026-09-26

## コンテキスト（背景）

P4 の逆戻り後に同じ task・iteration を再投入すると、古い実行の `gate.evaluated` が遅れて届くことがある。最後の投入へ task ID だけで判定を割り当てると、まだ検証されていない新しい投入が合格し、再承認待ちが解除される。投入時点より後に届いたことは、その投入を検査した証拠ではない。

## 判断（Decision）

- 新しく作る `gate.evaluated` の `payload.dispatch_seq` は、対応する `task.dispatched` の案件内 `seq` を指定する。task・iteration が一致し、判定より前の投入だけに適用する。
- 明示した `dispatch_seq` が不正、存在しない、または一致しないときは、別の投入にフォールバックしない。
- 参照がない旧イベントは、同じ task・iteration の投入が一つだけなら対応付ける。複数あれば判定自体は監査履歴へ残すが、どのタスクも完了させない。
- ゲート画面は対応した投入 seq を示し、対応不能な判定には「対象実行未特定（タスク完了には未使用）」を表示する。
- 他の作業イベントの既存の表示・対応付けは維持する。ここで保証するのはゲート判定によるタスク完了の誤帰属防止であり、実行基盤の run ID 管理ではない。

## 理由（Rationale）

投入 `seq` は既存イベントと状態にあり、追加の ID 発番を要しない。公開済みイベントは同一 task・iteration の再投入がなく、一意な旧形式として再生できる。曖昧な遅着判定は合格を推測するより未対応のまま残す方が、再承認待ちを誤って解除しない。

## 検討した代替案

| 代替案 | メリット | デメリット | 却下理由 |
|---|---|---|---|
| 最後の投入へ割り当てる | 既存実装が単純 | 旧判定の遅着で新投入が合格する | 誤承認を生む |
| 判定時刻が投入より後なら新投入へ割り当てる | 参照不要 | 到着順と検査対象は一致しない | 遅着を識別できない |
| 全イベントに新しい run ID を必須化する | 厳密 | 収録済みイベントの再生成が必要 | リプレイ範囲では既存 seq で足りる |

## 影響（Consequences）

### ポジティブな影響

同じ task・iteration の再投入後も、旧判定を新投入の完了に流用しない。画面上で対応不能な判定を識別できる。

### ネガティブな影響（トレードオフ）

複数投入に対して参照のない旧判定は、実際には新投入に対する結果であっても完了に使えない。元の判定と投入を結ぶ記録が必要になる。

### 将来の注意事項

実行基盤を実装する際は、`dispatch_seq` を生成元で確実に記録・検証し、並行実行や再送の run ID と対応付ける。収録済みの派生イベントを推測で書き換えない。
