# ADR-0005: 公開確認した Git の実物へのリンクを、イベントと別の索引で保持する

## ステータス

提案中（2026-09-23 の著者のリンク追加指示に基づく実装。PR で確認する）

## 日付

2026-09-23

## コンテキスト（背景）

REQ-029: リプレイ中に入力や出力の実物を参照したい。公開済みの J-SIX のものに限る。
元の非公開セッションを再抽出せず、実在を確かめたリンクだけ追加したい。
既存の証跡 URL は検査対象コミットを保存先とみなしていたが、公開 Git の `reports/` に実物が無い。
ADR-0001 の「公開」という記載も訂正する。抽出済みの判定結果があることと元ファイルの公開は別である。

## 判断（Decision）

- 本文は転載せず、`data/artifact-links.json` に案件別・イベント別のリンク索引を生成する。
- 生成時はローカル Git のコミットと通常ファイルの存在を確認し、GitHub API でリポジトリが PUBLIC で全参照コミットが公開されていることを確認してから書き出す。未コミットのファイルは使わない。
- 完全な commit SHA に固定する。公開 PR の squash 前コミットも対象であり、main の祖先であることは条件にしない。
- source は元文書・差分、output は変更後の成果物、input は固定イベントに明記された資料、reference は親コミットにある仕様・タスク定義。参考資料の実際の入力利用は未確認と表示する。
- プロンプトやセッション本文は読み込まない。架空案件、非公開セッション、保存版が不明なレポートにはリンクを作らない。ファイルが存在しても再構成イベントは再構成のまま表示する。
- 生成物とイベント列の SHA-256 を照合するテストで索引の陳腐化を検出する。Git からの再計算は `--check` で可能。

## 理由（Rationale）

同じ内容を固定版で検証でき、生成済みイベントの直接編集や非公開記録の再抽出が不要になる。
ブラウザは既知の公開リンクだけを表示し、実行時の GitHub API 呼び出しも不要になる。

## 検討した代替案

| 代替案 | メリット | デメリット | 却下理由 |
|---|---|---|---|
| source.ref や payload.commit から画面で URL を作る | 実装が小さい | 実在・公開・保存版を確認できない | 既存の証跡リンクで誤りが見つかった |
| 全イベントを再抽出して埋め込む | 形式を一元化できる | 非公開セッションが必要 | 公開 Git と生成済みイベントだけで追加できる |
| main の最新版へリンク | 修正済みの内容を読める | リプレイ当時の内容と変わる | 時点を固定する必要がある |

## 影響（Consequences）

### ポジティブな影響

- 仕様・コード・テスト・設計成果物を元の版で確認できる。
- 既存の実測／再構成ラベル、再生計算、イベントデータを変更しない。

### ネガティブな影響（トレードオフ）

- 索引生成に Git の履歴と GitHub CLI/API 接続が必要。通常のビルド・閲覧では不要。
- 公開 PR のコミットも、リポジトリ削除などで将来参照不能になる可能性はある。
- レポートの元ファイルは今回はリンクしない。公開・保存版・イベントとの一致を確認してから追加する必要がある。

### 将来の注意事項

- イベントを再生成したら索引も再生成する。索引も直接編集しない。
- AI が実際に読んだ入力を主張するには、別途その記録が必要。
