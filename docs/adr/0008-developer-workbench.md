# ADR-0008: 全工程を進める開発者ワークベンチをローカルに分離する

**状態**: 提案中 | **日付**: 2026-09-27 | **対象**: 単一PCの合成案件PoC

## 背景

公開Hubは過去記録を再生する閲覧専用サンプルである。[ADR-0007](0007-local-execution-poc.md)と[単一run設計](../specs/local-execution-design-spec.md)は、Hubによるタスク投入・検査とlocalhostの読取画面を定めた。しかし、開発者がJ-SIXのPhase 0〜6を一巡するには、案件作成、成果物提出、工程レビュー、差戻し、タスク実行、最終納品までの操作が必要である。ターミナルコマンドだけでは工程の不足理由や次の作業を一望しにくい。

## 決定

ローカルHubに**開発者ワークベンチ**と**中央監視**の二つのビューを設ける。前者は案件ごとの提出・模擬レビュー・実行要求を受け、後者は同じGit台帳から案件横断の状態と停止を示す。公開リプレイとは別の起動・bundle・データ源とし、公開Pagesへ書込APIや実runデータを載せない。コード編集は既存エディタと作業用worktreeで行い、Hubにエディタを内蔵しない。

ワークベンチの操作はlocalhost書込APIを経由し、画面と端末コマンドで同じドメイン判定を使う。APIはGit記録の最新SHA、対象成果物のhash、方針・process版、失効を再照合し、保存確認後だけ実行に進む。ブラウザの状態を正本としない。人間の判断は単一利用者のローカル模擬操作として記録し、顧客/第三者の本人認証済み承認に読み替えない。

最初に[要求Spec](../specs/developer-journey-requirement-spec.md)と[設計Spec](../specs/developer-journey-design-spec.md)を独立レビューし、実装は段階ごとに別レビューを通す。Hubのprocess lockは本体の対象commitへ明示的に更新し、リプレイの差分も検査する。

## 検討した代替案

| 案 | 判断 |
|---|---|
| 現行リプレイに書込操作を追加 | 実測・再構成・模擬承認・実runの来歴が混ざり、公開Pagesの「AIは動作しない」と矛盾するため採らない |
| ターミナルコマンドだけで全工程を進める | 初期の単一run検証には使えるが、開発者が案件の全工程と不足を追う体験の受入条件を満たしにくいため採らない |
| Hub内にコードエディタと独自IDEを作る | PoCの核心である工程/ゲート統制から外れ、既存CLI/エディタと重複するため採らない |
| 中央監視と開発者操作を別製品にする | 単一PC PoCでは同じ台帳とAPIを共有する別ビューで足りるため採らない |

## 影響と限界

- ローカル書込面にはOrigin/Host、CSRF、短期トークン、入力/サイズ制限を設ける。それでも同一OSユーザーの他プロセスに対する強い隔離や正式な承認者認証にはならない。
- Phase 0にはJ-SIX定義の承認ゲートを創作しない。後続Phaseの模擬判断は対象と版・理由を記録し、実顧客/第三者承認とは常時区別する。
- 実行器、全工程ワークベンチ、中央監視はこのADR時点では未実装。成果を示すのは新しい合成案件でのブラウザ一巡とGit/検査記録が揃った後に限る。
