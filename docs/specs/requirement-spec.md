# 要求 Spec — J-SIX Hub リプレイ型サンプル

**版**: 1.1 | **日付**: 2026-09-22 | **Phase**: P1（1.1 は初版公開後の改善要望による改訂）

構成は J-SIX の要求 Spec テンプレート（`templates/spec/requirement-spec.md`）に倣う。

---

## 1. 背景

### 1.1 解決したいこと

J-SIX Hub（J-SIX の工程を中央で統制する構想）は実装されていない。構想を記事・論文で説明するとき、
**Hub を導入すると開発者がどう統制され、開発がどう進むのか**を、文章と図だけでは伝えにくい。

### 1.2 本システムで行うこと

J-SIX の実際の実行記録（`data/events.jsonl`。approval-workflow の一周分）を、Hub の管理画面として時系列に再生する。
実際の AI は動かさない。

### 1.3 ステークホルダー

| ステークホルダー | 期待 |
|---|---|
| 記事・論文の読者 | 統制の様子（ゲートでの停止、承認、逸脱と回収、証跡）を画面で追える。どこまでが実測かが分かる |
| 著者 | 構想の説明に使える。Hub を J-SIX で開発した記録（ケーススタディ）になる |

## 2. スコープ

### 2.1 対象

案件一覧、Phase ボード、承認、タスクボードと AI の実行タイムライン、ゲート結果、証跡パッケージ、イベントの一覧、再生操作。

### 2.2 対象外

実際の AI の実行、認証・権限、DB・サーバ、画面上での編集、閉域環境への対応（`CLAUDE.md` のスコープ外）。
要求（REQ 単位）の閲覧とトレーサビリティの画面は、イベントに要求・トレーサビリティのデータが無いため、
データを拡張する別の変更で扱う（§3.5）。

## 3. 業務要件

### 3.1 ユースケース

| ID | ユースケース |
|---|---|
| UC-001 | 読者がリプレイを再生・一時停止・速度変更し、1イベントずつ進めたり戻したりする |
| UC-002 | 読者が任意の時点で、Phase ごとの状態とゲートの通過状況を見る |
| UC-003 | 読者がタスクの進み（hold-out → Red → Green → Refactor）と、ゲートによる停止を見る |
| UC-004 | 読者が承認の記録を見て、AI が書き込んだ承認が無効として扱われることを知る |
| UC-005 | 読者が逸脱（Phase 逆戻り・エスカレーション）の発生と回収を見る |
| UC-006 | 読者が各イベントの実測／再構成を見分け、再構成の根拠を読む |

### 3.2 要件（REQ）

| ID | 要件 |
|---|---|
| REQ-001 | すべての画面に「リプレイ（実際の AI は動作していません）」を常時表示する |
| REQ-002 | 表示するすべてのイベントに、実測／再構成のラベルを付ける。再構成のイベントは根拠（`basis`）を読めるようにする |
| REQ-003 | 再生・一時停止・速度変更・1イベント進む・1イベント戻る・任意の位置への移動ができる |
| REQ-004 | 表示する状態は、イベント列の先頭 N 件（N は再生位置）を適用した結果とする |
| REQ-005 | Phase とゲートの名前・順序・構成は、J-SIX のプロセス定義（固定した版）から生成する。画面のコードに Phase やゲートの一覧を書かない |
| REQ-006 | Phase ボードに、各 Phase の状態（未着手 / 進行中 / 承認済み）と、そのゲートの状況を表示する |
| REQ-007 | タスクボードに、各タスクの状態と現在の工程、AI（サブエージェント）の実行の履歴を表示する |
| REQ-008 | ゲート結果の画面に、ゲートの判定ごとに層・チェック・結果・要約と、同じ内容の繰り返し回数を表示する |
| REQ-009 | 承認の画面に承認の記録を表示する。承認者が人間の役割でない承認（AI が書き込んだもの）は無効として区別し、Phase を承認済みにしない |
| REQ-010 | 逸脱（開いたもの・閉じたもの）を表示する。Phase 逆戻りが開いたら、戻り先以降の Phase を進行中に戻す |
| REQ-011 | 前の Phase が承認済みでないのに後の Phase の作業が行われた場合、順序違反として表示する |
| REQ-012 | 証跡パッケージの画面に、証跡パッケージの生成結果と承認の状況を表示し、J-SIX リポジトリの該当ファイルへリンクする |
| REQ-013 | 案件一覧に案件を表示し、プロセス定義の版と、実測／再構成の件数を示す |
| REQ-014 | プロセス定義の出典（J-SIX、CC BY 4.0、版）を表示する |
| REQ-015 | 複数の案件を1本の時間軸で再生し、案件一覧（Program の概観）に各案件の進み具合と注意点（順序違反・ゲートでの停止・開いている逸脱）を並べる（ADR-0003） |
| REQ-016 | 架空の案件・Program には、どの画面でも「架空」と表示する |
| REQ-017 | 初回表示時に、画面の各エリアを順に吹き出しで説明するガイドツアーを表示する。ツアーはいつでも開き直せ、閉じられる |
| REQ-018 | 各エリアの見出しの「？」から、そのエリアの説明を吹き出しで表示できる |
| REQ-019 | 再生位置のイベントについて、「いま起きたこと」と「Hub が何を統制したか」を平易な文で表示する |
| REQ-020 | 出来事の記録（イベントの一覧）で、統制に関わる出来事（ゲートでの停止・無効な承認・逸脱・順序違反）を目立たせ、それだけに絞り込める |
| REQ-021 | 出来事の記録に凡例（実測／再構成／架空、人間／AI／Hub）を表示し、各行に時刻・案件・実行者を示す |

### 3.3 受入条件と Property（PROP）

| ID | 受入条件 |
|---|---|
| AC-001 | 案件一覧・Phase ボード・タスク・ゲート・承認・証跡のどの画面にも、リプレイの表示がある（REQ-001） |
| AC-002 | 再構成のイベントを選ぶと根拠の文が表示される（REQ-002） |
| AC-003 | 1イベント進めて1イベント戻すと、元と同じ表示になる（REQ-003, REQ-004） |
| AC-004 | 2026-09-19 の AI による承認の直後、P1 は承認済みにならず、無効な承認として表示される（REQ-009） |
| AC-005 | 設計レビュー後の Phase 逆戻りで、P1 以降が進行中に戻る（REQ-010） |
| AC-006 | Phase ボードの Phase 名とゲート名が、プロセス定義の `phases[].name` と `gates[].name` に一致する（REQ-005, REQ-006） |
| AC-007 | 案件一覧に3件の案件が並び、架空の案件に「架空」と表示される（REQ-015, REQ-016） |
| AC-008 | 初回表示でガイドツアーが始まり、「次へ」で全ステップを進め、「閉じる」で終わる。2回目以降は自動では始まらない（REQ-017） |
| AC-009 | monthly-billing の G1 スコープ検査での停止の時点で、「いま起きたこと」がゲートによる停止を説明する（REQ-019） |
| AC-010 | 「統制ポイントだけ」に絞ると、ゲートでの停止・無効な承認・逸脱の開始・順序違反のイベントだけが残る（REQ-020） |

| ID | Property |
|---|---|
| PROP-001 | 任意の N について、`replay(events, process, N)` は、N までをどの順で進めたか戻したかに依らず同じ状態を返す（決定性） |
| PROP-002 | 任意の N について、N 件目までの状態は N+1 件目以降のイベントの内容に依存しない（先頭 N 件だけで決まる） |
| PROP-003 | 任意の N について、承認済みの Phase には、人間の役割による有効な承認が少なくとも1件ある（per_task の Phase を除く） |
| PROP-004 | 任意の N について、状態に現れる実測・再構成の件数の合計は N に等しい |

### 3.4 hold-out 受入テストの対象

AC-004・AC-005（実データでの統制の場面）。

### 3.5 今後の拡張（本版の対象外）

- 要求（REQ 単位）の閲覧、トレーサビリティ（REQ → タスク → テスト → コード → 設計書）の画面。
  J-SIX の `docs/traceability.md` 等をコミット時点で読み取る抽出を追加してから作る

### 3.6 非機能要件

| 項目 | 要求 |
|---|---|
| 可用性 | GitHub Pages に依存。サーバは持たない |
| 性能 | イベント数百件で、1イベントの移動に体感できる遅延が無いこと（計測はしない） |
| 運用・保守性 | リプレイの計算は画面から独立し、単体テストで検証できる |
| セキュリティ | 外部への送信をしない。読み取り専用 |
| アクセシビリティ | セマンティック HTML。キーボードで再生操作ができる |

## 4. 制約

- 実測でない出来事を実測として表示しない
