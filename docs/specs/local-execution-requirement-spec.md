# 要求 Spec — 単一 PC の中央実行型 Hub PoC

**版**: 0.1 | **日付**: 2026-09-27 | **状態**: 提案中（実装・実証前）

本書は [J-SIX Hub の PoC 限定 ADR-0009](https://github.com/SeckeyJP/j-six/blob/main/docs/control-plane/adr/0009-local-cli-execution-poc.md) を、このリポジトリで実装するための要求である。現行の[リプレイ要求 Spec](requirement-spec.md)と公開 Pages は引き続き再生専用とし、本書の「実行」を備えているとは扱わない。J-SIX の Phase/Gate 自体は変更しない。最終的なプロセスの正本は J-SIX `docs/J-SIX.md`、実行・判定の設計条件は `docs/control-plane/execution-contract.md` とする。

## 1. 背景・対象・境界

現行リプレイは過去記録を表示するが、Hub がタスクを許可して AI を起動し、候補を検査・受入れする経路はない。初回 PoC は **この PC の一人の利用者**が、公開または合成 fixture の小さなタスクを、Hub 管理下の Codex CLI または Claude Code CLI に投入し、Git 記録から状態を再構築できるかを検証する。作業者が Hub 外で CLI を直接動かすことは防げないため、PoC が示せるのは Hub 経由の run と候補取込みの管理だけである。

| 対象 | 内容 |
|---|---|
| 入力 | 固定した合成 fixture の commit、タスク、許可パス、方針・検査定義の版 |
| 実行 | 同時に1 run。保存済みのサブスクリプション認証を使うローカル `codex exec` または `claude -p` の一方 |
| 出力 | worktree の候補差分、CLI のイベント参照、独立検査結果、Git 記録、ローカル候補 ref、読取画面 |
| 対象外 | 実企業 PJ のデータ、複数利用者・ベンダー、閉域・オンプレ、無人継続運用、API キー／Agent SDK 実行、公開 Pages からの実行、モデルの自動振分け |

この PoC は強い OS 隔離、worker からの認証 cache や記録先へのアクセス遮断、署名による証跡の真正性、承認者の本人確認、Hub 外の起動経路の閉鎖、成果物の業務妥当性を証明しない。ローカル操作の「人間確認」はこの利用者の明示操作の記録であり、将来構想の本人認証済み承認と同一視しない。
PoC の「許可」は合成 fixture に限るローカル試験判定であり、実行契約 R1 の署名・独立発行者と R5 の本人確認を満たす正式な工程許可ではない。実 run の成功を J-SIX Phase/Gate の承認済みへ変換しない。

## 2. ユースケース

| ID | 操作と期待 |
|---|---|
| UC-LE-01 | 利用者が合成タスク、対象 commit、Codex/Claude の一方を選び、Hub が投入可否と理由を表示する |
| UC-LE-02 | Hub が許可と実行要求を非公開 Git に保存確認した後だけ CLI を起動し、候補・イベントを回収する |
| UC-LE-03 | 独立検査が候補の差分範囲・必須チェック・対象/方針版を照合し、不合格を保持する |
| UC-LE-04 | 利用者が証拠を見てローカル確認操作を行い、Hub が最新状態を再判定して候補 ref に取込む、または保留する |
| UC-LE-05 | 保存失敗・競合・失効・timeout・結果不明・上限到達の run を安全に保留し、再起動後に Git 記録から復元する |

## 3. 要求

| ID | 要求 |
|---|---|
| REQ-LE-001 | run を始める前に対象 repo/commit、タスク、許可パス、プロセス/方針/検査定義の hash、必須検査集合、選択 CLI、run ID、command ID を固定する。対象集合を worker が縮小・拡張しない |
| REQ-LE-002 | Hub の判断処理は対象・方針・検査・失効を照合し、合成 fixture のローカル試験に限る `許可`・`例外付き許可`・`保留` と理由を出す。方針外の例外、未知状態、欠落した必須条件を自動で許可しない。正式な工程適合の判定とは表示しない |
| REQ-LE-003 | 正本は公開 repo と分けたリモートなしの非公開ローカル Git とする。許可・実行要求・検査・確認・結果・失効は対象と版を伴う追記記録として保存し、Hub の状態は Git から再構築できる |
| REQ-LE-004 | 記録先 ref の期待 SHA を条件に、許可と実行要求の保存・再読込が成功した後だけ CLI を起動する。保存失敗・競合・応答不明時は起動せず、読み直して再判定する |
| REQ-LE-005 | 利用者が run ごとに CLI を選ぶ。Hub は ChatGPT ログインの Codex CLI、`claude.ai` サブスクリプションの Claude Code CLI 以外を拒否する。API キー、access token、代替 provider が実行環境にある場合と、追加クレジット/課金条件を確認できない場合は起動しない |
| REQ-LE-006 | API キー・SDK・従量課金へ自動で切り替えない。利用枠到達・追加クレジット案内・認証失効時は停止する。同時実行は1 run とし、初回実 CLI 検証は各 CLI の読取1回と小さな合成編集1回までにする |
| REQ-LE-007 | CLI は run 専用 worktree で最小権限の非対話モードとして起動し、マシン共通の設定・Hook・規則を迂回しない。起動時の版、認証方式、適用を確認できた Hook、入力/出力の hash と取得できたモデル識別子を、秘密値を除いて記録する |
| REQ-LE-008 | worktree の全差分と CLI イベントを回収する。worker が出した「検査合格」「承認済み」の文字列は有効な検査・承認として扱わない。生ログ、認証 cache、個人情報、絶対パスは公開 repo や Git 記録に入れない |
| REQ-LE-009 | worker とは別の検査主体が、固定された候補、保護された方針・検査定義で決定論的チェックを実行する。必須集合の欠落・skip・unknown・failed、対象外変更、版不一致は取込みを止め、元の結果を上書きしない |
| REQ-LE-010 | ローカル確認は検査結果と対象版を示した後の明示操作とし、操作対象・時刻・理由を Git に保存する。確認だけで検査未達を passed に変更せず、本人認証済み承認として表示しない |
| REQ-LE-011 | 取込み直前に失効、対象/方針/検査版、記録先 ref と候補 ref を再確認する。許された候補だけ期待 SHA 付きでローカル候補 ref に反映し、公開 main や保護ブランチを自動更新しない |
| REQ-LE-012 | 同じ run の同時 dispatch は排他的に1件だけ開始する。timeout、SIGINT、記録応答消失、結果不明は `unknown` または保留として記録し、同じ run/command ID で照合する。一意に未実行と確認できない CLI 操作を自動再送せず、旧実行の停止不明時に新 run を起動しない |
| REQ-LE-013 | 方針の通常改訂と緊急失効を区別する。緊急失効後は新規起動・取込みを止め、停止未確認の結果や取消し後の遅着結果を隔離する。取消し要求を停止完了と表示しない |
| REQ-LE-014 | 再起動時は非公開 Git の記録から状態を再構築し、未確定 run と外部作用を照合する。Git だけで外部作用の exactly-once や完了を推定しない |
| REQ-LE-015 | localhost の読取画面に対象/方針版、run 状態、検査・確認・例外・未検証の範囲と証拠参照を表示する。現行リプレイの実測/再構成/架空イベントとはデータ源と表示を分ける |
| REQ-LE-016 | ローカル PoC の実 run は当該 run の範囲だけを示す。性能・ROI・企業実 PJ・複数ベンダーの統制実証に一般化しない |

## 4. 受入条件と性質

| ID | 関連要求 | 合成入力での期待 |
|---|---|---|
| AC-LE-01 | 001〜004 | 保存確認前の強制停止では CLI 起動回数0。保存済み要求と許可を Git から再構築でき、記録先 ref 競合なら再判定まで投入しない |
| AC-LE-02 | 005〜007 | 両 CLI の subscription ログインで読取 smoke を各1回。API key/access token/provider 指定や不明な追加クレジット設定では起動0、認証・上限不明も保留 |
| AC-LE-03 | 008〜009 | 許可外ファイル変更、必須検査の欠落・skip・失敗、検査設定の worker 側変更を拒否し、候補を反映しない |
| AC-LE-04 | 010〜011 | 未確認の候補は ref を更新しない。確認後も版が変われば保留。合致時だけ期待 SHA 付きで候補 ref を更新する |
| AC-LE-05 | 012〜014 | 同じ run の同時 dispatch は spawn 1回以下。要求保存後から spawn 前の失効では spawn 0回。起動直後の記録喪失、timeout、二重応答、取消し後の遅着結果で重複投入・古い許可による反映をしない。不明は照合待ちのまま残す |
| AC-LE-06 | 015〜016 | 公開 Pages は引き続き「リプレイ、AI は動作しない」と表示。ローカル画面は実 run と未証明範囲を表示し、Git から再起動復元できる |

| ID | 性質（Property） |
|---|---|
| PROP-LE-01 | 任意の run と履歴について、保存確認済みの許可・要求が存在しなければ CLI の投入イベントを作らない（REQ-LE-004） |
| PROP-LE-02 | 任意の候補について、有効方針の必須検査に欠落・未達・対象不一致が1件でもあれば候補 ref を更新しない（REQ-LE-009/011） |
| PROP-LE-03 | 任意の記録先/候補 ref 競合、失効、結果不明について、古い対象・許可・確認記録で候補 ref を進めない（REQ-LE-011〜014） |

Property の ID 出現は構造的な対応であり、期待値の妥当性や独立性の証明にはならない。実装時は別担当が反例と hold-out の小さな合成シナリオを用意し、worker から保護する。実 CLI 呼出しを伴う試験は上記回数に限り、拒否系は fake adapter で検証する。

## 5. 非機能・運用上の条件

| 区分 | PoC の条件と境界 |
|---|---|
| 可用性 | 単一 PC・手動起動。障害時の自動復旧時間目標は置かず、未確定 run を保留して手動照合できることを優先 |
| 性能・拡張性 | 同時1 run。壁時計時間・出力サイズを run 設定で制限する。大規模並列・ROI は評価しない |
| 運用・保守性 | Git 記録から状態再構築。生ログは非公開ローカル領域に置き、保持・削除は PoC 実施前に決める |
| 移行性 | 既存リプレイのデータと process.lock は移行しない。PoC の公開・外部環境移設は別判断 |
| セキュリティ | 秘密値を記録・公開しない。最小権限とマシン共通制御を維持するが、同一 OS ユーザー間の強い隔離は保証しない |
| システム環境 | この PC のローカル CLI と Git。外部クラウドの開発者 API、閉域、組織運用は対象外 |

コード着手条件は本書・[Design Spec](local-execution-design-spec.md)・ADR の独立レビュー通過。最終デモの成功は合成 fixture の当該 run の観測に限る。
